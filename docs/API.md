# LifeOS REST API Specification

Complete documentation for the LifeOS REST API backend.

## Base URL
- Development: `http://localhost:5000/api`
- Production: `https://YOUR-BACKEND.onrender.com/api`

---

## 1. Health & System

### GET `/api/health`
Check backend server connectivity.
- **Authentication**: None
- **Response**:
```json
{
  "status": "ok",
  "service": "LifeOS API",
  "timestamp": "2026-08-29T11:30:00.000Z"
}
```

---

## 2. Authentication

### POST `/api/auth/register`
Start a new user registration and send an email verification code.
- **Authentication**: None
- **Request Body**:
```json
{
  "name": "Jane Architect",
  "email": "jane@example.com",
  "password": "Password123!"
}
```
- **Response (202 Accepted)**:
```json
{
  "success": true,
  "data": {
    "email": "jane@example.com",
    "expiresAt": "2026-08-29T11:40:00.000Z"
  },
  "message": "Verification code sent to your email"
}
```

### POST `/api/auth/register/verify`
Complete registration with the six-digit code sent by email.
- **Request Body**: `{ "email": "jane@example.com", "code": "123456" }`
- **Response**: Returns the newly created `user` and JWT `token`.

### POST `/api/auth/register/resend`
Send a new verification code for a pending registration.
- **Request Body**: `{ "email": "jane@example.com" }`

### POST `/api/auth/login`
Authenticate user with email and password.
- **Authentication**: None
- **Request Body**:
```json
{
  "email": "jane@example.com",
  "password": "Password123!"
}
```
- **Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "user": {
      "id": "uuid-v4",
      "name": "Jane Architect",
      "email": "jane@example.com",
      "createdAt": "2026-08-29T11:30:00.000Z"
    },
    "token": "eyJhbGciOiJIUzI1Ni..."
  },
  "message": "Login successful"
}
```

### GET `/api/auth/me`
Retrieve authenticated user profile.
- **Authentication**: `Bearer <token>`
- **Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "id": "uuid-v4",
    "name": "Jane Architect",
    "email": "jane@example.com",
    "createdAt": "2026-08-29T11:30:00.000Z",
    "settings": { ... }
  }
}
```

### POST `/api/auth/logout`
Sign out authenticated session.
- **Authentication**: `Bearer <token>`

## 3. Deadline & Task Management

### GET `/api/tasks`
Retrieve tasks with optional filtering, search, and sorting.
- **Authentication**: `Bearer <token>`
- **Query Parameters**:
  - `category`: `ASSIGNMENT` | `EXAM` | `PROJECT` | `HACKATHON` | `JOB` | `INTERNSHIP` | `SCHOLARSHIP` | `MEETING` | `EVENT` | `PERSONAL` | `OTHER`
  - `priority`: `LOW` | `MEDIUM` | `HIGH` | `CRITICAL`
  - `status`: `TODO` | `IN_PROGRESS` | `COMPLETED` | `CANCELLED`
  - `search`: string
  - `sortBy`: `dueDate` | `priority` | `createdAt` | `title`
  - `sortOrder`: `asc` | `desc`
- **Response (200 OK)**:
```json
{
  "success": true,
  "data": {
    "tasks": [
      {
        "id": "uuid-task-id",
        "userId": "uuid-user-id",
        "title": "Submit DBMS Assignment",
        "description": "ER diagram normalization",
        "category": "ASSIGNMENT",
        "priority": "CRITICAL",
        "status": "TODO",
        "dueDate": "2026-08-30T18:00:00.000Z",
        "estimatedHours": 4,
        "riskLevel": "HIGH_RISK",
        "createdAt": "2026-08-29T11:30:00.000Z",
        "updatedAt": "2026-08-29T11:30:00.000Z"
      }
    ],
    "total": 1,
    "page": 1,
    "totalPages": 1
  }
}
```

### POST `/api/tasks`
Create a new task.
- **Authentication**: `Bearer <token>`
- **Request Body**:
```json
{
  "title": "DBMS Assignment",
  "description": "ER Diagram normalization",
  "category": "ASSIGNMENT",
  "priority": "HIGH",
  "dueDate": "2026-08-30T18:00:00.000Z",
  "estimatedHours": 3.5
}
```

### POST `/api/tasks/batch`
Batch create subtasks generated by AI.
- **Authentication**: `Bearer <token>`

### GET `/api/tasks/:id`
Retrieve single task details by ID.
- **Authentication**: `Bearer <token>`

### PUT `/api/tasks/:id`
Update task attributes.
- **Authentication**: `Bearer <token>`

### DELETE `/api/tasks/:id`
Delete a task.
- **Authentication**: `Bearer <token>`

### PATCH `/api/tasks/:id/status`
Update task status (`TODO`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`).
- **Authentication**: `Bearer <token>`

### PATCH `/api/tasks/:id/complete`
Mark task as completed immediately.
- **Authentication**: `Bearer <token>`

## 4. AI Services

### POST `/api/ai/chat`
Ask AI assistant questions with real PostgreSQL database task context.
- **Authentication**: `Bearer <token>`
- **Request Body**:
```json
{
  "message": "What should I work on today?",
  "conversationId": "optional-uuid"
}
```

### POST `/api/ai/daily-plan`
Generate realistic Morning/Afternoon/Evening schedule from user tasks.
- **Authentication**: `Bearer <token>`

### POST `/api/ai/task-breakdown`
Decompose complex goals into 4-6 subtasks.
- **Authentication**: `Bearer <token>`
- **Request Body**:
```json
{
  "taskTitle": "Build my final year project",
  "estimatedHours": 20
}
```

### POST `/api/ai/risk-analysis`
Perform AI risk assessment for a specific task.
- **Authentication**: `Bearer <token>`
- **Request Body**:
```json
{
  "taskId": "uuid-task-id"
}
```

### POST `/api/ai/parse-nl`
Parse conversational prompt into structured deadline task.
- **Authentication**: `Bearer <token>`
- **Request Body**:
```json
{
  "prompt": "Submit DBMS assignment tomorrow at 6 PM"
}
```

## 5. Notifications, Search, Analytics, Settings

### GET `/api/notifications`
Retrieve active user notifications and unread count.

### PATCH `/api/notifications/read-all`
Mark all notifications as read.

### GET `/api/search?q=query`
Global search across user tasks, categories, and descriptions.

### GET `/api/analytics/dashboard`
Retrieve high-level dashboard counters and Recharts distributions.

### GET `/api/analytics/full`
Retrieve 7-day velocity trend and completion rates.

### GET `/api/settings` & PUT `/api/settings`
Manage user preferences (theme, timezone, notifications).
